# ClickyCanvas AI 客服 Agent：项目 PRD

版本：P6.7｜日期：2026-10-11

## 1. 项目定位

为虚构电商商家 ClickyCanvas 构建中文优先的 AI 客服 Agent 原型，帮助顾客完成键盘选购、政策咨询、订单查询和售后转人工。项目重点不是让模型自由聊天，而是让回答建立在可验证的商品、政策和订单事实之上，并在需要时记住会话条件、调用受限工具和安全转人工。

## 2. 用户与问题

### 目标用户

- 不熟悉键盘参数、希望快速缩小选择范围的消费者；
- 需要查询退货、保修、配送规则的消费者；
- 遇到故障、延迟或退款争议，需要明确下一步的消费者。

### 核心问题

传统 FAQ 只能返回静态答案，通用大模型又可能编造商品规格、承诺退款或重复追问。用户需要的是：基于当前上下文的结论、简短理由和下一步。

## 3. 产品目标

1. 让顾客用自然语言描述预算、用途、配列、连接方式和噪声偏好，并逐轮修改条件。
2. 对商品和订单事实使用结构化数据，对政策问题使用可追踪知识检索。
3. 对焦虑、挫败和高风险场景采用不同承接策略；高风险问题不让模型自行承诺退款或赔偿。
4. 通过固定回归、独立挑战集和人工盲评发现并修复真实可见的回答问题。

## 4. MVP 范围

### 顾客侧能力

- 商品搜索、详情、比较和条件追问；
- 配送、退货、保修、故障排查政策问答；
- 模拟订单状态查询（订单号 + 演示验证码）；
- 到货损坏、退款争议和安全风险转人工案件；
- 匿名会话内保存选购条件 24 小时，可主动清除。

### 非目标

- 不接入真实商家订单、支付、退款或真实客服系统；
- 不把本地演示数据当作线上业务数据；
- 不宣称已有真实用户满意度或生产级 SLA。

## 5. 关键体验规则

- 顾客只看到结论、必要理由和下一步，不看到模型名、检索过程和内部追踪字段。
- 商品候选数量必须与实际展示数量一致。
- 只有缺少关键条件时才追问，且一次只问一个最必要的问题。
- 情绪承接最多一次，随后推进问题处理。
- 安全风险先提示停止使用并断开电源，再创建人工案件，不承诺退款或赔偿结果。

## 6. 验收标准

- 固定 33 案例、39 轮评估中：硬条件违反率为 0，事实一致率和候选覆盖率达到当前回归目标；
- 售前评估 58/58，固定评估 84/84；
- 高风险场景不越权承诺，工具调用有边界和脱敏轨迹；
- 关键回答不出现内部来源话术，候选数量和回答一致；
- 所有结论在质量报告中标记证据等级和适用范围。
