# ClickyCanvas AI 客服 Agent：3 分钟面试演示脚本

## 0:00—0:20 项目定位

“这是一个中文优先的电商客服 Agent 原型。它解决的不是单纯聊天，而是让客服回答建立在商品、政策和订单事实之上，并在需要时记住上下文、调用受限工具和转人工。我重点做了评测体系和失败归因。”

## 0:20—1:00 商品推荐与条件记忆

输入：`想买无线键盘`

讲解：系统返回实际候选数量和商品信息；不展示“我根据什么检索”的内部过程。继续输入：`桌面小，改成 65 配列`，展示上一轮条件被保留并收敛到匹配候选。

强调：商品事实来自结构化目录，模型不能自行修改价格、配列或轴体。

## 1:00—1:40 政策回答与下一步

输入：`我不明白退货到底怎么走流程`

讲解：系统直接说明订单号、退货期限、售后案件和寄回地址确认方式，只保留与问题相关的政策片段，不把知识库标题和检索过程展示给顾客。

## 1:40—2:20 情绪承接与故障排查

输入：`按键没反应，试了好几次还是不行`

讲解：系统只承接一次“抱歉让您反复尝试仍没解决”，随后给排查步骤和人工售后所需材料，不重复安慰，也不直接承诺换新。

可选高风险演示：`键盘起火了，要求马上退款`。系统先提示停止使用并断开电源，再创建人工案件，不承诺退款或赔偿。

## 2:20—2:50 评测证据

“固定 33 案例、39 轮评估从修复前 14/33 提升到 33/33；硬条件违反率从 25% 降到 0%。独立挑战集有 60 个案例、70 个轮次，另外做了 12 题本人盲评。盲评暴露的冗余话术和候选计数问题已经修复，修复后回归评估为售前 58/58、固定评估 84/84。”

## 2:50—3:00 诚实边界

“这些结果来自本地虚构数据和单人盲评，不能证明真实用户满意度或生产 SLA。下一步如果进入真实试点，我会先接入脱敏真实问法、增加独立评审和线上失败监控，再评估是否扩大自动化范围。”
