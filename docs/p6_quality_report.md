# P6 质量验证报告

状态：P6.1—P6.6 已完成；P6.6 人工盲评为单评审内部盲评。本文档是本阶段唯一结果入口；本轮数字来自固定本地演示数据和单评审复核，不代表真实顾客满意度。

## 目标

### P6.2 口径与模型连接状态

`scripts/evaluate_holdout.py` 现在在 JSON 报告中写入 `metric_definitions`，并支持 `--output data/runtime/p6_holdout_deterministic.json`，避免终端编码影响复核。默认分母固定为对话轮次；候选覆盖、排序和硬条件只统计声明 `expected_product_ids` 的轮次；模型回退只在 DeepSeek 可调用轮次中统计。

DeepSeek 初次请求暴露两个工程问题：沙盒默认禁止直连外网，以及思考模式占满短 JSON 的输出上限。通过一次最小权限网络检查确认 API 可用后，`app/llm.py` 改为关闭思考模式并把 JSON 输出上限提高到 700/900 tokens；随后完整 33 条、39 轮对照成功完成。模型状态为 `rewritten=28`、`fallback=3`、高风险/澄清/通用问题跳过 8 轮。模型改写次数没有作为质量指标。

修复后重新运行同一 33 条、39 轮：deterministic 和 DeepSeek 均为 33/33 案例通过。DeepSeek 状态为 `rewritten=31`、`fallback=2`、`skipped_clarification=2`、`skipped_high_risk=4`，回退率 6.06%，P95 1729.21ms。回退仍由事实保护机制记录，不把改写次数当作质量指标。

## P6.6 独立挑战与人工盲评（2026-10-11）

自动挑战集与人工盲评分开报告。自动挑战集冻结 60 个案例、70 个对话轮次，覆盖 paraphrase、mixed_context、boundary、emotion 四类；修复后 deterministic 案例通过率 96.7%、轮次通过率 97.1%、安全边界违规 0，DeepSeek 案例通过率 83.3%、轮次通过率 85.7%、安全边界违规 0。逐轮结果位于被 Git 忽略的 `data/runtime/p6_independent_*.json`。

人工盲评表为 `docs/independent_review_sheet.md`，从四类各抽取 3 题，共 12 题。评审者只看顾客输入和 A/B 回答，没有查看模型名称、内部意图或自动评估结果；本轮为单评审内部盲评，证据等级为 `single_reviewer_blind_review`，不能称为独立用户研究。

| 人工盲评指标 | 结果 |
| --- | ---: |
| 完成案例 | 12/12 |
| 总体通过 | 8/12（66.7%） |
| A 偏好 | 1/12（8.3%） |
| B 偏好 | 4/12（33.3%） |
| 相同/无法区分 | 7/12（58.3%） |
| A 五项平均分 | 1.42/2 |
| B 五项平均分 | 1.55/2 |
| 合并五项平均分 | 1.48/2 |

主要人工反馈：

- 商品推荐中出现“我根据……找到”“实际声音和使用感受受环境影响”“以上信息适合作为初步筛选参考”等顾客不需要看到的内部或泛化表述；这些句子在问题不需要时会增加机械感。
- 候选数量与实际展示数量不一致：回答声称找到 4 个候选，但只列出 3 个，影响事实可信度。
- 退货和保修场景中，更短、直接给出流程和下一步的回答明显更合适；“我们直接继续处理”被认为不自然。
- 多个 A/B 回答内容完全相同，平局率较高，说明部分场景模型改写对顾客不可见，不能把所有差异都归因给模型能力。

第 5 题的信心字段未填写，已在盲评表中标记为“未填写”，没有补猜。该缺口不改变 12 题的偏好、分数和通过判断，但后续若要发布完整汇总应补齐或明确排除该字段。

### 盲评后修复（2026-10-11）

根据上述顾客可见反馈，已完成三项最小修复：商品推荐改为展示实际返回的全部候选，并将标题改为直接面向顾客的“为您筛选到”；移除与当前问题无关的听感免责声明和泛化能力清单，只在缺少预算时追问预算上限；政策回答按问题选择一到两段相关事实并去掉知识库段落标题；挫败情绪改用“我先帮您继续排查/处理”等自然承接。

修复同时调整了润色事实保护规则：仍要求商品、价格和轴体事实保留，但不再强制顾客重复内部筛选条件。验证结果为：售前评估 58/58、固定评估 84/84、购物/情绪/工具/holdout 单元测试 32/32。以上是回归证据，尚未对 12 题重新人工盲评，因此原盲评分数仍代表修复前基线。
